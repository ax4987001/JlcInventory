# 通用 AI 助手开发规范与系统规则模板

> **说明**：这是一份提炼自 Godot 游戏项目、适用于跨技术栈的通用 AI 代理（如 Trae / Cursor / GitHub Copilot 等）行为约束规则模板。您可以将本文件的内容复制并配置到其他项目（如 Android、前端、后端等项目）的系统提示词或对应的规则文件中，以规范 AI 的编码习惯、工作流和文档维护方式。

## 1. 核心工作流与版本控制 (Agent Workflow & Git)
1. **本地快照备份 (Commit)**：AI 在每次完成有效的功能修改、Bug 修复或代码重构后，**必须**主动使用 `git add .` 和 `git commit` 将代码提交到本地进行快照备份，以便随时可以安全回退。
2. **Commit 规范**：所有的 Commit 提交信息必须使用**中文**编写，格式为 `[模块] 动作：简短描述`。
3. **禁止私自推送 (No Push)**：**绝对禁止** AI 在没有用户明确允许的情况下私自执行 `git push` 操作！必须先询问用户并获得授权。
4. **编辑失败处理**：如果在代码修改过程中导致文件结构混乱或解析失败，AI 应优先尝试使用 Git (`git restore` 等) 恢复到上一个正常的本地快照版本。

## 2. 诊断、调试与日志 (Diagnostics & Debugging)
1. **零警告交付**：新编写的代码**禁止**出现任何静态检查（Linter）错误或警告。交付前必须确保代码在语法和类型检查上是 100% 安全的。
2. **被动读取真实日志**：在排查 Bug、逻辑卡死或任何运行时异常时，AI 必须优先主动读取项目生成的**真实本地日志文件**（如 Android 的 logcat 导出文件、Web 控制台日志等），而不是盲目猜测或依赖用户口述。
3. **禁止私自运行项目**：除非是执行脚本化单元测试，否则**绝对禁止** AI 私自通过终端启动主项目。所有的项目运行、App 编译安装等操作**必须**由用户亲自在 IDE 或真实设备上执行。AI 需要运行时，必须明确提示用户：“现在需要您运行项目并提供日志”。

## 3. 知识库与文档驱动开发 (Document-Driven Development)
1. **主动追加日志**：在完成重大需求、修复 Bug 或重构后，AI 必须主动将任务描述、解决思路和文件变更追加记录到 `docs/chat_history.md`（或相应的开发日志文件）末尾。
2. **沉淀知识库**：遇到并解决新的复杂问题、深层架构 Bug 后，**必须**将现象和解决思路以结构化方式记录到 `docs/problems_and_solutions.md` 中。
3. **优先查阅文档**：在处理复杂系统前，AI **必须**优先读取文档目录下的架构索引文件（如 `docs/index.md` 或 README），严禁一上来就对数万行的核心代码进行盲目的全局 Grep 搜索。
4. **强制同步更新文档**：重构核心模块后，必须主动提议将最新的逻辑流、依赖关系和避坑指南更新到对应的架构 Markdown 文件中，保证代码与文档的“真源一致”。

## 4. 终端与代码修改安全 (Terminal & Code Editing)
1. **禁止使用终端脚本修改文件**：**严禁**使用 PowerShell、Python 脚本、`sed` 等终端命令来进行文本编辑、代码修改或文件覆写操作（极易导致系统级编码损坏或乱码）。
2. **强制使用内置工具**：所有的文件编辑必须且只能通过 AI 助手内置的直接修改工具（如 `SearchReplace`、`Write` 等内置能力）进行。
3. **修改前强制备份**：在对核心大文件进行毁灭性重构前，应确保 Git 工作区干净（已 Commit）或手动备份。
4. **严禁破坏性编辑与死代码**：替换代码块必须包含完整的函数头或判断块，确保缩进正确。严禁保留未使用的变量、未调用的方法或大段被注释掉的历史废弃代码。

## 5. 编码与架构通用规范 (Coding & Architecture Norms)
1. **强类型安全**：在支持强类型或类型推断的语言中（如 Kotlin, Java, TypeScript, Swift），必须严格遵守类型声明，避免隐式 Any/Dynamic 类型滥用导致的运行时崩溃。
2. **模块化与解耦**：代码必须按职责分层（如 MVC/MVVM, Models/Controllers/Views），严禁将所有逻辑揉捏在一个庞大的上帝类（God Class）中。
3. **规范化通信**：
   - **向下通信**：父组件调用子组件，通过公有方法。
   - **向上通信**：子组件通知父组件，**必须**通过事件总线、接口回调（Callback/Delegate）或响应式流（Flow/LiveData）。严禁子组件硬编码持有父组件的强引用。
4. **空指针安全 (Null Safety)**：所有跨模块访问状态、UI 节点操作时，必须先进行 `null` 检查或前置拦截验证，绝不能想当然认为外部依赖已被正确注入。
5. **多语言与本地化 (Localization)**：**禁止硬编码 UI 文本**。所有展示给用户的文本必须通过本地化资源文件（如 Android 的 `strings.xml`，前端的 `i18n.json`）获取，并在新增词条时同步更新多语言文件。

## 6. UI 交互与体验规范 (UI/UX Norms)
1. **事件穿透阻断**：在存在多级模态窗口（Modal）、全屏弹窗或对话框时，必须在底层或通过属性配置进行事件消费，**严禁任何点击、滑动事件穿透到下层界面**。
2. **多级窗口逐级关闭**：当存在多个覆盖层时，全局的“返回”或“取消”交互（如 Android 的物理 Back 键、PC 的右键/Esc）必须实现**逐级关闭**（先关最上层，再关下层）。
3. **风格统一**：新增的 UI 界面必须严格对齐项目现有的视觉规范（如统一的圆角、阴影、主题色、字体大小等），禁止生造异类风格。
